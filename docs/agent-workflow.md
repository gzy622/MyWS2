# 智能体工作基线

本文件定义智能体在本仓库中的工作边界与维护方式。它不定义产品需求、视觉规范、交互细节或代码实现；这些事实分别保留在对应的现行文档中。

## 规则目标

工作规则只解决五件事：确定需求来源、控制改动范围、选择验证方式、记录未消除的风险、统一协作称呼。任何不能服务于这五件事的长期要求，都不写入本文件。

## 信息优先级

冲突按以下顺序处理：

1. 用户在当前任务中的明确要求。
2. 与改动职责直接对应的现行文档。
3. 当前实现及其自动化检查。
4. 历史档案。

同级现行文档发生冲突时，先按文档职责判断；仍不能确定时，保持现状，记录待确认项，不擅自选择产品行为。

## 标准工作循环

| 阶段 | 必须产出 | 不做项 |
| --- | --- | --- |
| 定位 | 纳入/不纳入范围，受影响页面、状态和文件 | 不根据文件名或记忆推断实现 |
| 约束 | 命中文档路由，读取必要章节 | 不通读全部现行文档 |
| 实施 | 与任务一致的最小改动 | 不捎带重命名、格式化或依赖升级 |
| 验证 | 与改动直接相关的检查结果 | 不把未运行的链路写为已验证 |
| 交付 | 结果、检查和剩余风险 | 不隐藏限制或冲突 |

## 验证边界

- 默认只执行本地、快速且与改动直接相关的检查。
- 浏览器自动验收和 Android 链路测试必须由用户在当前任务明确要求后执行。
- 涉及删除、覆盖、外部服务写入、权限扩大或不可逆迁移时，先确认精确目标和授权范围。
- 检查无法运行时，说明原因、未覆盖范围与剩余风险。

## 文档维护

- `AGENTS.md` 只保留入口、阅读路由、强制边界和交付约定。
- `docs/README.md` 只保留文档地图、文档职责和档案定位。
- 产品、视觉、交互、工程、架构和术语文档只记录各自职责内的现行事实。
- 已完成的方案、复盘和阶段记录移入 `docs/archive/`，不参与日常规则优先级。
- 新增长期规则前，必须写明适用范围、触发条件、验证方式和不适用范围；缺少其中任一项时，不新增该规则。

## 首批额外规则

本轮采用以下最小规则集，不引入固定任务模板、强制工具链或特定框架偏好：

| 规则 | 可核对结果 | 主要风险 |
| --- | --- | --- |
| 任务先定位 | 每次实施前记录范围与影响面 | 需求本身模糊时只能确认边界，不能替代业务决定 |
| 按职责读文档 | 改动可对应到一条阅读路由 | 旧文档职责重叠时需要记录待确认项 |
| 最小改动 | 差异只包含任务所需内容 | 跨模块问题可能需要后续独立任务 |
| 验证如实记录 | 已运行与未运行的检查明确区分 | 未授权链路不覆盖真实环境 |
| 风险外显 | 交付中列出剩余限制和冲突 | 风险不能由文档规则自动消除 |
| 协作称呼统一 | 需要明确分工时可使用用户、Lead、Maker，可省略符号且英文不区分大小写 | 称呼完全可选，具体 Agent 和模型以当前任务为准；直接任务指令始终有效 |

后续仅在重复出现且可验证的工作问题上增加规则。单次偏好、临时任务限制和未确认的技术判断保留在当前任务上下文，不写入长期工作文档。
