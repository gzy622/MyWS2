# 00 · 产品与范围 Spec

## 1. 产品定义

这是一个**教师工作台的移动端高保真 Demo**，用于演示信息架构、视觉风格与触控交互，不是完整业务系统。

- 语言：简体中文。
- 主要设备：手机竖屏；桌面端仅以手机容器预览。
- 技术形态：零依赖原生 HTML、CSS、ES Modules，无构建步骤。
- 当前内容为占位内容；登记网格中的 46 个姓名是 Demo 占位名单，不代表真实学生。除非任务明确要求，不得虚构真实成绩、学校或业务数据。

## 2. 固定信息架构

主导航固定为 3 页，每页固定 2 个子视图：

| 页索引 | 主页面 | 子视图 0 | 子视图 1 |
| --- | --- | --- | --- |
| 0 | 安排 | 班干 | 值日 |
| 1 | 登记 | 网格 | 座位 |
| 2 | 课程 | 课表 | 成绩 |

刷新后的初始状态：

- 当前主页面为索引 `1`（登记，中间页）。
- 三个页面的子视图均为索引 `0`。
- 抽屉、字号浮层关闭，Toast 隐藏。
- 导航与子视图不恢复上一次状态。
- 学生姓名字号默认 `16px`；若存在有效持久化值，则恢复为上次选择的 `14～18px` 字号。

## 3. 固定界面区域

从上到下：

1. 顶栏：左侧“菜单”、居中显示当前主页面名称、右侧“更多”。
2. 内容视口：3 个可横向切换的页面；每页自身可纵向滚动。
3. 底部主导航：用 3 个图标分别进入安排、登记、课程，并保留子视图指示点。
4. 网格字号浮层：仅在登记页 / 网格视图中由“更多”打开。
5. 通用菜单：从底部弹出的抽屉。
6. 临时反馈：顶部 Toast。

## 4. 修改边界

除非需求明确要求，否则：

- 不增加登录、后端、路由、网络请求、数据持久化或设置系统。
- 不改变主页面数量、名称、顺序和子视图数量；登记页当前不显示分段控件，通过重复点击底部“登记”切换网格 / 座位。
- 不将 Demo 擅自改成后台管理页、卡片瀑布流或桌面 Dashboard。
- 不把占位按钮实现成无法撤销的真实操作。
- 不更换视觉主题，不添加品牌 Logo、插画、照片或装饰性 emoji。
- 除学生姓名字号外，不新增界面状态持久化；导航、子视图、抽屉和浮层状态始终在刷新后重置。

## 5. 内容写作规则

- 标题短而直接；按钮优先使用 2～6 个汉字。
- 辅助文字说明“是什么/将做什么”，避免营销口号和空泛形容词。
- 同层级文案保持平行结构。
- 占位内容明确标注“占位”“待完善”或“即将推出”，不可伪装为已完成能力。
- 不使用英文作为主要操作文案；页面眉题中的现有英文标签可以保留。

## 6. Spec 优先级

发生冲突时按以下顺序处理：

1. 用户当前任务中的明确要求。
2. 本目录的 spec。
3. `ARCHITECTURE.md`。
4. 当前实现。

如果 spec 未覆盖某项，不进行猜测式重设计：保留现状并做满足需求的最小改动。
